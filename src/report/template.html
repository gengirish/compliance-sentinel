Appendix B: Methodology and disclaimer

How this report was produced

  • Regulatory sources are checked daily. Only rules whose content hash changed since the last check enter an audit.
  • Rule text is split into section-aware chunks and embedded into a vector store. The target repository is indexed the same way at the snapshot shown on the cover.
  • For each rule, obligations that software must implement are extracted with the chunks that state them.
  • For each obligation, code evidence is gathered by keyword search and vector similarity, then assessed as compliant, a violation, or needing review.
  • Every citation is then checked without a model: each regulation chunk must exist and belong to the rule, and each file:line range must exist in the audited snapshot. Citations that fail are dropped, and a verdict left without both kinds of support is downgraded to "needs review".

Limits

  • The audit sees only the indexed repository. Controls implemented in infrastructure, vendor systems or policy documents are invisible to it.
  • A "compliant" result means supporting code was found, not that the obligation is fully met.
  • Coverage is limited to the rules listed in Appendix A.

Disclaimer

This report is automated decision support. It is not legal advice and it does not guarantee compliance or complete coverage of any regulation. Findings should be reviewed by qualified counsel and engineers before any action is taken on them.
